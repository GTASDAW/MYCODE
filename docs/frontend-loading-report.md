入口 JS 原始字节减少 309,964，约 24.3%；逐文件 gzip 估算减少 87,384，约 22.1%。gzip 使用独立 level-9 压缩，不包含 HTTP 头，不等于浏览器实际传输；本机对照服务器使用 identity 响应，Nginx 缓存与缺失资源合同另由真实容器验证。

产物图确认 13 个独立动态页面入口，首页没有这些页面本体、29 个管理延后源模块及 3 个 Table 实现。该检查没有声称穷尽所有第三方模块归属。公共导航、反馈和活动筛选仍需要共享组件，候选仍有约 623 kB 块触发默认 500 kB 提示；没有修改阈值或为消除提示额外拆分公共职责。

构建证据保存源摘要、版本和每个 JS/CSS 的 raw/gzip/SHA256，测量前再与磁盘 manifest 和真实文件清单核对，防止把被覆盖的输出当成原产物。标准容器构建也输出内部图，专项从运行中的 Nginx 容器取得并与实际 HTML 入口匹配；这些文件不公开提供。

## 冷加载方法

桌面尺寸 1280×800、手机尺寸 390×844，均使用同一桌面 Chrome 154.0.8037.93 和 Chromium CDP；这是响应式视口测量，不代表手机硬件性能。每个视口分别对两版各执行 10 次，以 AB/BA 交错；每次使用全新上下文、禁用浏览器缓存及 Service Worker。固定下载 1.6 Mbps、上传 0.75 Mbps、延迟 150 ms，不施加额外 CPU 限制。

两个仅绑定回环地址的生产静态服务器提供各自固定产物，复用同一个真实 Java/MySQL 只读活动列表。测量期间不并行运行其他浏览器或写业务回归，不保存 Cookie、HAR、trace 或 storage state。网络字节来自 Chromium `Network.loadingFinished.encodedDataLength`，JS/CSS 记录包含 Chromium 计入的 HTTP 传输开销，与上述静态估算分开。

`listVisibleMs` 是首张活动卡片已存在且具有正布局高度时的观测时间，表示列表内容布局就绪；不是独立的标准 Web Vital，也不证明整张卡片都位于视口内或已经完成绘制。LCP 和 DOMContentLoaded 独立保留；读取时的 1 秒观测等待不被加到这些时间戳中。所有样本、超时、资源失败与初始化失败保留，失败使测量命令失败，不删除失败以挑选更好结果。本机结论不能推广为生产首屏 SLA，也没有 CI 耗时门禁。

四组各 10 次均成功，0 失败、0 超时；JS/CSS 均来自真实冷 HTTP 响应，活动接口返回 200 且包含真实活动。下面是每组全部 10 次的中位数：

## 复现与材料

安装项目现有两份 lockfile 的依赖并确认本项目后端健康后，在根目录执行：

```powershell
npm run build:loading
npm run check:loading
npm run measure:loading
```

最终测量要求前端源码已提交，且 5184/5185 端口空闲；脚本核对固定基线与候选产物，只启停自己的回环静态服务器。构建图、原始样本和自动汇总保存在忽略目录 `.runtime/frontend-loading/`；第一次主动中止的试运行另存 `trial-interrupted-1/`，不计入正式对照。

真实 JS/CSS 失败、缺失资源、慢加载、URL 与会话恢复见 [加载指南](frontend-loading-guide.md)，完整测试与 CI 事实见 [验证记录](verification.md)。

最终候选的 [CI 38848847748](https://github.com/GTASDAW/MYCODE/actions/runs/38848847748) 五任务全部成功。默认和 Redis Nginx 各通过 132 项业务浏览器、20 项生产加载及 8 项严格限流浏览器检查；CI 保存构建图、字节合同与浏览器原始诊断。本机上述 40 次交错测量的原始样本保留在 `.runtime/frontend-loading/measurements.json`，不冒称 CI 主机上重复得到相同耗时。

# 前端按需加载与页面恢复

公开活动发现页直接加载，其余业务页面按路由加载。导航外壳、Router、认证和通知 Provider 保持原位置，切换页面不重新建立这些状态；原业务 API、数据库迁移和写流程保持原合同。实际产物和冷加载方法见 [对照记录](frontend-loading-report.md)，完整浏览器和 CI 结果见 [验证记录](verification.md)。

## 页面加载边界

懒组件在模块顶层声明，以显式映射方式使用页面现有的具名导出。管理页面和需要登录的页面，其 ProtectedRoute 权限检查仍在懒组件外，拒绝访问时不会先请求相应管理页面模块或管理数据；登录表单本身是公开的懒加载页面，代码拆分不代替服务端权限检查。

`Suspense` 和错误边界只覆盖 Layout 中的页面内容，顶栏与侧栏继续可用。尚未加载的目标页面显示“正在打开页面…”和骨架；路径变化定义新的加载边界，筛选、分页或 hash 变化不重挂正常页面。错误状态随路径或认证代次变化清除，不重新创建 Provider。

页面模块或关联 CSS 加载失败时显示“页面暂时无法打开”，不展示原始异常或资源 URL。用户可选择：

- “重新加载当前页面”：执行真实整页刷新，保留当前路径、查询与 hash；刷新后从服务端重新确认现有 Cookie Session。
- “返回活动列表”：通过既有导航回到直接加载的发现页。

没有自动重试或自动刷新循环。React 会缓存同一 `lazy` 对象的拒绝结果，仅重置错误边界或修改 key 不保证重新下载模块，因此恢复按钮明确说明它会刷新当前页面。返回列表也不代表已经修复原模块；再次访问失败的模块仍可能需要整页刷新。

## 构建与静态资源

构建采用 Vite 默认动态拆包，移除原来将 React、组件库和底层组件按目录合并为几个大块的手工规则。公共外壳需要的依赖仍可能较大；保留构建默认警告阈值，不把警告消失作为优化完成的标准。

构建证据同时记录入口静态 imports、动态入口及模块归属。首页不包含其余业务页面本体，并额外核对首页不需要的 Table 实现；不能只看 chunk 文件名，也不能用“已经在首页的模块都算公共模块”的循环定义证明没有泄漏。组件库 barrel 的静态依赖图可能包含最终被删除的导出，需要结合实际产物判断。

默认和 Redis 两份 Nginx 配置使用相同的静态资源合同：

| 请求 | 行为 |
| --- | --- |
| HTML 与业务深链回退后的 HTML | `Cache-Control: no-cache`，允许客户端重新验证版本 |
| 成功返回的带 hash 资源 | 长期 `public, max-age=31536000, immutable` 缓存 |
| 缺失的 `/assets/` 文件 | 真实 404、纯文本错误和 `no-store`，不返回应用 HTML，不使用长期缓存 |
| 构建证据目录 | 不通过网页公开提供 |

现有 `/api` 转发、来源头处理及双实例行为保持。网站继续仅在本地开发与演示，不增加 Service Worker、自动预取或缓存框架。

## 如何核对优化

固定基线为 `c98df13603074bb48eff89ec3785e47d186ffebf`。基线与候选使用同一 lockfile、Node、Vite 和生产构建参数，输出到忽略目录；源码身份、依赖图与产物字节一起保留。

原始 JS/CSS 文件字节、逐文件 gzip 压缩估算与浏览器真实传输分别报告。首次首页不下载其他业务页面，进入某页时才加载对应模块及缺少的共享依赖，复访使用已加载模块；总产物大小与首次需要下载的大小不是同一个指标。

冷加载使用真实生产资源和同一个只读 Java/MySQL 接口，桌面与手机分别以新浏览器上下文交错测量优化前后各 10 次。网络条件、浏览器版本、视口、原始样本及失败必须保留；测量期间不并行运行写业务回归。耗时为该本机条件下的观测，不设 CI 耗时门禁，也不从字节差直接推导生产首屏收益。

生产专项在独立浏览器上下文中让真实 JS/CSS 请求延迟或失败，核对局部加载、外壳可用、手动刷新保留地址和会话、离开后不晚挂旧页面，以及未授权路径不下载管理代码。常规业务回归继续覆盖原有认证代次、CSRF、URL 返回和数据清理；语法或单元测试不能替代这些浏览器检查。

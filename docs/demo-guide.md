# 五分钟演示：从发布、候补递补到签到

这份流程用于本机业务演示。先启动本项目，打开 `http://127.0.0.1:5173`；使用容器环境时打开 `http://127.0.0.1:8088`。演示账号为 `admin / Admin123!` 和 `demo / Demo123!`。流程不依赖公网服务，递补与活动取消写入本项目站内通知，不发送邮件或短信。

## 演示前准备

- 确认活动列表能打开，`/api/health` 返回 `UP`。
- 登录和注册有 [固定窗口限流](auth-rate-limit.md)。连续尝试收到 429 时保留输入，等待页面倒计时结束再手动重试；更换 Session 不会重置来源次数。
- 准备活动 A 的标题、介绍和地点，例如“业务演示 YYYYMMDD HHmm”，开始时间设为北京时间明天 20:00，名额 **1**，选择分类；在下方主流程中现场发布。封面可另做可选演示，不修改已有样例。
- 提前创建另一场准确归属的签到活动 B，开始设为几分钟后的真实时间；用新注册的专用普通账号在开始前报名，记录两场活动的 ID 和标题。B 自然开始后才能签到，不修改数据库时间或已有样例来跳过限制。创建 B、注册及预先报名属于准备工作。
- 预先用普通窗口登录专用普通账号、无痕窗口登录 `admin`，或使用两个独立浏览器上下文；两个普通窗口通常共享 Cookie。管理员也可报名，用这两个身份即可演示递补，不修改预置账号资料。若只能用一个上下文，每次先退出再换账号，相应延长演示时间，不硬凑五分钟。
- 预先打开 [架构与接口说明](architecture.md)、[并发报名复盘](concurrency-review.md) 和 [验证记录](verification.md)。实际测试结果以验证记录和当前 CI 运行为准。

## 可选的两分钟账户流程

演示自主注册时，先从登录页进入“注册账号”，填写一个未使用的用户名、昵称和密码。注册成功会回到登录页，账号已填入，需要自己登录；服务端只创建普通用户，不能从表单选择管理员。

用新账号报名一场未来活动，再从账号菜单打开“个人中心”，修改昵称并保存。账号菜单随即显示新昵称，刷新个人中心后仍保留；退出再登录，“我的报名”仍有刚才的记录。登录名保持固定，昵称只作为展示资料。

解释 `uq_users_username`、密码哈希和可信登录 ID：重复用户名由数据库唯一约束决定；昵称修改不接受其他人的身份；资料读取查数据库最新值，不替换整个 Session 身份与 CSRF。使用普通窗口与无痕窗口，或两个不同浏览器，分别登录同一账号以建立独立会话；可展示重新打开个人中心后读取新昵称，以及退出一个会话不会使另一个退出。两个普通窗口通常共享 Cookie，不能用于演示独立会话。当前没有跨窗口推送，不能说成所有已打开页面自动同步。代码路径见 [账户指南](account-guide.md#按一次请求阅读代码)。

## 可选的一分钟改密演示

先新注册一个专用账号，不修改预置 `admin` 或 `demo` 密码。使用普通窗口与无痕窗口建立两个独立登录，从一个窗口进入个人中心，输入原密码、新密码和一致的确认值。提交成功后应回到登录页并提示密码已更新；用新密码登录回个人中心。另一个窗口再次读取个人记录时要求重新登录，旧密码不能重新登录；已经打开的页面没有自动推送。

说明数据库凭据版本为何比遍历 Redis Session 更直接：原哈希与版本同次读取，改密用版本条件更新，旧身份每个请求校验一次，迟到保存也不能恢复。网络中断后只能显示“结果未确认”，通过手动重新登录确认，不把断网当作回滚。详细规则和代码路径见 [改密指南](password-change-guide.md)。

## 可选的一分钟活动发现演示

匿名打开“发现活动”，按自己发布的唯一标题或地点查询，切换“报名中”“已满员”“已取消”，确认上方统计表示整个筛选范围。匹配活动超过 12 场时可以翻页，每页数量也可改变；少量结果正常只有一页，不需要修改已有样例数据制造页数。

从筛选结果打开详情，刷新后点“返回活动列表”，条件仍保留。也可以从详情登录并报名，再返回列表，检查个人状态和剩余名额更新；搜索条件写入 URL，分享的是条件而不是固定数据快照。失败可重新加载，空结果可清除筛选。代码与一致性解释见 [活动发现指南](activity-discovery.md)。

## 可选的一分钟活动分类演示

用管理员新发布两场不同分类的未来活动，例如“技术交流”和“运动户外”，不改已有样例。在发现页按唯一标题片段和分类查询，再叠加“报名中”，确认卡片分类与全量统计；进入详情、登录后返回，URL 保留分类。管理列表也可筛选、翻页、刷新和前进后退，条件保留。

把自己刚创建且未开始活动的分类改成“文化艺术”，其他字段保持原值，再保存相同内容一次；操作记录应只有一次分类 `EDIT`，中文前后值完整显示。旧活动显示未分类，旧审计不补字段，开始时间和名额仍固定。接口与代码依据见 [分类指南](activity-category-guide.md)，实际运行结果见 [验证记录](verification.md)。

## 可选的恢复演练讲解

按 README 在本机运行 `npm run verify:restore`，等待实际结果，不手工清空演示库制造故障。展示受限目录中 completed/sourcePreserved/cleanupGraceful 的最终摘要及两张恢复后页面截图，解释两次恢复为什么能分别证明原数据与非空图片/六表样本。说明真实登录/报名/取消及约束检查在新库进行、原服务保持，约一分钟仅为本机小样本整体验收时间；完整 SQL 和凭据文件不作为演示附件发送。

## 可选的一分钟封面演示

新建一场未来活动，从详情进入编辑页，选择不超过 2 MiB 的 PNG/JPEG 并上传。先在基本信息中输入尚未保存的标题，验证保存封面不会覆盖草稿；返回详情和发现页展示图片，再更换或移除，检查操作记录中的封面内容编号变化。演示坏图或超限时只使用独立测试文件；说明服务端会校验并重编码，封面通过数据库在两实例共享，公开图片不代表报名。既有样例默认没有封面，不为演示修改。

## 可选的一分钟日历导出演示

从带分类条件的发现页进入未取消活动详情，不登录也可以点击“下载日历”，检查文件名为 `activity-{id}.ics`。说明文件只含公开活动资料、记录开始时间，并在已提供结束时输出结束时间；未提供时不猜测时长。导入不代表报名，后续编辑或取消不会自动同步；已开始活动也可用于补录，已取消活动不能导出新日程。

在自己新建的测试活动中演示页面加载后由另一会话修改地点，再下载应使用最新地点；原页面及报名状态不被这次读取覆盖。若活动已被取消，下载操作提示刷新。客户端实机导入只有实际执行后才能写入验证结果，不把浏览器下载说成客户端兼容；不为演示修改既有样例。

## 可选的一分钟收藏演示

从带分类条件的发现页进入详情，点击“登录后收藏”，登录后应回到原详情并保留列表来源。点击收藏，打开侧栏“我的收藏”，查看活动状态、分类和北京时间收藏时间；进入详情再返回，分页条件保留。取消收藏后列表重新读取，末页为空时修正页码。已开始或已取消活动仍可收藏，说明收藏是书签，不占报名名额；不为演示修改原始样例数据。

## 可选的一分钟个人报名演示

登录后打开“我的报名”，按活动标题或地点提交关键词，再切换“已报名”“候补”“已取消”，观察当前筛选总数变化、本人全部历史的四项统计保持同一口径。输入未提交的草稿后翻页或刷新，仍使用已提交条件；查询和重置回第一页。记录超过 10 条时翻页，选择每页 20 或 50 条；没有足够记录时不修改样例或直接造数据。刷新、前进后退保留 URL 条件，从记录进详情并刷新，点“返回我的报名”仍回原关键词、筛选和页码。

从未开始活动的详情取消有效报名，再返回原“已报名”页，列表重新读取；最后一页减少时自动回合法页。已经自然开始且由管理员确认签到的记录显示本人北京时间，上方“已签到”只是“已报名”的子集；候补和已取消显示签到“不适用”，普通用户不能自行签到，也看不到签到操作人。

解释一次聚合加一次当前页联表如何共同读取快照；旧完整数组保留，但由逐条加载活动改为一次联表。实际确认的是应用数据 SELECT 次数与执行计划，没有测量个人接口的延迟或吞吐提升。合同与阅读路径见 [我的报名指南](my-registrations-guide.md)。

## 五分钟流程

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:50 | `admin` 发布活动 A，普通账号按唯一标题找到并进入详情 | 前后端独立工程通过 API 交互；创建成功产生新 ID 与 `CREATE` 记录 |
| 0:50–1:35 | 普通账号报名 A；独立 `admin` 窗口打开同一详情并加入候补 | 普通账号 `ACTIVE`、管理员 `WAITING`，有效人数仍为 1；管理员报名也遵守名额规则 |
| 1:35–2:20 | 普通账号取消 A；`admin` 打开递补通知并进入详情 | 最早候补在同一事务递补为 `ACTIVE` 并写通知；有效人数仍为 1，候补归零 |
| 2:20–3:05 | `admin` 打开“我的报名”，按 A 标题查询，再按地点查询、刷新并从详情返回 | 列表与 total 按条件筛选，四项统计始终覆盖本人全部记录；草稿与已提交 URL 条件分开 |
| 3:05–4:00 | `admin` 查看 A 名单、导出 CSV，再查看创建操作记录 | 管理员已报名、普通账号已取消；CSV 按筛选导出并保护 Excel 文本，用户报名不写管理员审计 |
| 4:00–5:00 | B 已自然开始时刷新其名单，管理员为准备好的有效报名签到；查看 `CHECK_IN` 记录 | 首次可信操作人与时间保留；A 未开始不能签到。对应 [事务源码](concurrency-review.md) 和 [验证记录](verification.md) 可继续展开 |

结束时管理员可以取消自己在尚未开始的 A 中的报名，使其有效人数回到 0。手工发布的演示活动和已开始的 B 会保留，系统当前没有活动删除接口。自动测试创建的临时数据使用单独的精确清理机制，不应以标题前缀批量删除。

五分钟是手工讲解的建议安排，不是自动化耗时或性能承诺。若 B 尚未开始，等待真实时间或把签到另作可选演示，不跳过安全条件。改密、恢复、封面等旁支按提问选做；本轮连续主流程的实际验证范围以验证记录为准。

## 可选的活动编辑与取消演示

用另一场尚未开始、名额为 1 的新活动单独演示整场取消：

1. 管理员从详情进入“编辑活动”，修改标题、介绍和地点，保存后刷新详情；开始、结束时间和名额只读且不变。
2. 用 `demo` 报名，再用 `admin` 加入候补，确认有效人数 1、候补人数 1。
3. 管理员点击“取消活动”，填写原因并确认；详情显示“活动已取消”、原因和北京时间，有效人数与候补均为 0。
4. 在报名名单查看两条保留的已取消记录；活动管理选择“已取消”，概览的取消活动数增加。换 `demo` 打开“我的报名”，也能看到同一原因。
5. 说明重复的有效取消请求保留首次原因和时间、活动不可恢复；已取消详情不能继续报名。手工演示不需要直接改数据库或触发自动测试清理。

讲解报名与组织者取消的两种锁顺序：报名先成功也会随后被整场取消；取消先提交时，后续报名返回 `ACTIVITY_CANCELLED`。两者最终人数均为 0，而历史 ID 保留。真实 MySQL 对锁顺序、开始边界与异常回滚的证据见 [活动生命周期指南](activity-lifecycle.md#实际验证与阅读路径) 和 [验证记录](verification.md)。

## 可选的一分钟管理员操作记录演示

用本次独立新建且尚未开始的活动演示；不修改原账号昵称或已有样例时间。管理员从活动管理点击该行“操作记录”，应看到这场新活动的 `CREATE`。回到编辑页真实修改标题或介绍，再保存相同内容一次；重新打开记录，应只有一次 `EDIT`，详情展示完整前后值，名称注明操作时快照。

切换类型、活动 ID 与每页数量，刷新或前进后退，确认 URL 保留条件；打开只读详情再关闭，不产生新记录。若此前对这场活动完成首次取消，查看其 `CANCEL`，重复有效取消不新增；已自然开始的独立签到活动可查看首次 `CHECK_IN` 及目标用户，重复签到仍一条。没有相应历史时不直接造记录，旧数据升级 V6 不回填。

解释记录追加与业务共用事务：插入失败会一起回滚，不是“业务先成功、之后尽力记日志”。列表不加载长变化正文，详情才读取；普通用户不能读取，记录没有修改或删除按钮。两种身份请使用普通窗口和无痕窗口，或两个独立浏览器上下文。字段、微秒时间与代码依据见 [管理员操作记录指南](audit-log-guide.md)，实际运行结果见 [验证记录](verification.md)。

## 可选的一分钟通知演示

在上述真实递补之后，`admin` 点击顶栏铃铛或“通知中心”，找到这场唯一标题的“候补递补成功”消息，点击“标记已读”；当前页重新读取，铃铛显示本人全部未读数。切换未读/已读筛选、刷新 URL 或翻页，条件保留；重复标读保留第一次时间，打开详情本身不会自动标读。

使用另一场形成有效报名和候补的新活动做整场取消，两个当时参与者分别登录后打开通知中心，查看相同公开原因；此前已经自行取消的人不收到这类消息。没有轮询，其他窗口产生变化后需打开或刷新通知页。强调标题和原因是事件快照，当前详情是最新活动信息；普通用户不能查看或标读他人的通知。完整条件和代码路径见 [站内通知指南](notification-guide.md)。

## 可选的签到与导出演示

提前发布另一场即将开始的新活动，让 `demo` 在开始前报名；不要修改已有样例活动或直接把数据库开始时间调到过去。自然到达开始时间后再进行以下操作，等待期间可讲解代码和事务：

1. 管理员打开该活动“报名名单”，开始前签到按钮禁用；到时间后点击“刷新名单”，查看整场有效、已签到和未签到人数。
2. 对 `demo` 点击“确认签到”，核对弹窗中的昵称与账号后确认。名单显示首次北京时间和操作人，已签到加 1、未签到减 1，有效人数不变。
3. 切换“未签到”，确认该参与者不在当前集合，但上方统计仍是整场有效报名者；回到“已签到”查看首次记录。
4. 点击“导出 CSV”，用 Excel 打开中文文件，查看签到状态、北京时间和管理员。说明导出全部符合两类筛选的记录，而非当前页；空条件结果仅表头，超 20,000 条会明确拒绝。
5. 解释重复请求保留首次时间与操作人、签到不改变报名更新时间或候补 FIFO；昵称与 ID 使用文本保护，文件面向人工查看，不是无损数据导入格式。

成功签到不提供撤销，也没有自动截止，因此支持稍后补录；已经开始的活动不能再正常取消报名，手工活动与签到历史会保留。只有自动测试自己的准确归属数据可使用相应清理流程。接口、字段与验证路径见 [签到与导出指南](checkin-export-guide.md)，实际桌面/手机下载结果看 [验证记录](verification.md)。

## 可选的一分钟签到分析演示

管理员打开概览，在“活动签到分析”选择已自然开始活动的北京时间日期范围并查询，核对活动场次、有效报名、已签到、未签到和当前签到比例。切换分页时，全量统计不由当前页推算；选择没有有效报名的活动时比例为“不适用”。日期、页码和数量写入 URL，刷新、前进后退保留条件。

从某行进入报名名单确认一次真实签到，再用浏览器返回概览，检查重新读取后的已签到加 1、未签到减 1、有效报名不变。解释 1/1 与 1/9 两场活动整体为 2/10，即 20%，不能平均各场比例。没有结束时间且支持补录，只能称当前签到进度，未签到不是最终缺席。详细合同与代码路径见 [签到分析指南](attendance-guide.md)。

## 代码怎么讲

按一个请求的实际路径讲清楚，不必逐行背代码：

1. `frontend/src/api.ts` 统一发送 HTTP 请求和 CSRF 信息，认证状态由现有 AuthProvider 管理。
2. `SecurityConfiguration` 根据 Cookie Session 识别用户；服务端校验权限与 CSRF，报名人来自可信登录身份。
3. Controller 接收活动 ID，`RegistrationService.register` / `cancel` 开启 `READ_COMMITTED` 事务。
4. `ActivityMapper.lockById` 使用 `SELECT ... WHERE id = ? FOR UPDATE` 锁定这场活动；随后普通读取报名状态。
5. 满员报名进入 `WAITING`；取消 `ACTIVE` 后，`RegistrationMapper.findEarliestWaiting` 按 `updated_at ASC, id ASC LIMIT 1` 取最早候补者，更新状态和人数并插入递补通知后一起提交。
6. 接口返回真实最新状态，页面更新；刷新直达仍从数据库读取记录。

现有 [架构图](architecture.md#技术分工) 展示 React、统一入口、Spring Security、Controller、Service、MyBatis、MySQL 和两种 Session 存储方式。双实例的会话流向另见 [共享 Session 指南](shared-session.md)。

## 可选的一分钟共享登录演示

使用 Redis Compose overlay 时，先登录，在浏览器网络面板观察 `/api/auth/me` 的 `X-Gather-Backend` 响应头：重复读取会分配给不同后端，但身份一致。然后仅在自己启动的这组本地演示中重启 A：

```powershell
docker compose -f compose.yaml -f compose.redis.yaml restart backend
```

等待 `/api/health` 恢复后刷新页面，会话未过期且 Redis 可用时，仍保持同一登录。最后退出，再说明两个后端都无法恢复原身份。完整的跨实例 CSRF、权限、退出和闲置失效证据以验证脚本及 [验证记录](verification.md) 为准；3 秒 TTL 演练只在隔离 CI 执行，不修改手工演示环境。

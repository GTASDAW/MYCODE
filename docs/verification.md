## 真实数据库结果

100 个不同用户通过独立事务，同时竞争一个活动的 10 个名额：成功 10 个，满员拒绝 90 个，最终有效报名记录和活动人数均为 10。测试使用虚拟线程并发任务和 20 个数据库连接，验证一致性，不把这个结果当作系统吞吐量指标。

50 个不同活动各自同时发生首次报名：50 个全部成功，没有死锁。这个用例覆盖了同活动竞争测试看不到的空报名键间隙锁问题。

另外验证了重复报名、重复取消、重新报名、已开始活动、外键插入失败后的事务回滚、权限检查、CSRF 轮换和重启初始化不覆盖已有数据。

## 浏览器验证范围

在桌面和手机视口分别验证：

- 活动列表来自真实接口，详情能够直接打开，没有横向溢出。
- 管理员发布活动，普通用户报名、取消、重新报名；记录与接口数据一致，刷新后仍然保留。
- 普通用户不能进入管理员页面；退出后需要重新登录才能查看个人记录。
- 错误密码保持未登录，并展示服务端错误。
- 服务端 Session 失效后，旧 CSRF Token 只触发一次安全刷新，随后回到登录并继续原活动操作。
- 报名响应延迟时切换到另一场活动，迟到响应不会覆盖新详情。

检查了桌面和手机页面截图，并清理了本次浏览器验证创建的测试活动。

## 运行边界

当前演示地址是本机 `http://127.0.0.1:5173`，服务保留运行，尚未发布到公网。

仓库已经提供 Docker Compose、前后端 Dockerfile 和 Nginx 同源配置。当前机器没有 Docker，因此没有实际执行容器构建或容器部署；这些配置需要在具备 Docker 的环境中进一步验证。

JDK 与 MySQL 使用项目内的工具目录，本地服务只绑定回环地址。启动脚本会核对端口进程，停止脚本只终止记录并核实过的本项目进程。已实际验证本项目停止与重启后，其他项目的服务仍保持运行。

Session 当前在单个 Java 进程的内存中，重启后需要重新登录；数据库活动和报名记录保留。Redis、多实例部署、支付、文件上传和公开注册不在第一版中。
